# Zigbee OTA для ESP32-H2 CO2

В этой версии добавлены OTA Upgrade client (ZCL `0x0019`), запись образа через ESP-IDF OTA API и упаковщик образа для Zigbee2MQTT.

## Версии

- `zcl_version` — версия самого стандарта ZCL. Оставляем значение SDK (`0x08`); номер нашей прошивки туда не записывается.
- `FW_APPLICATION_VERSION` — однобайтовый атрибут Basic cluster `ApplicationVersion` (`0x0001`), который Z2M может показать как версию приложения.
- `OTA_FILE_VERSION` — 32-битная версия в OTA-кластере и OTA-файле. Она должна возрастать при каждом выпуске. В OTA-коде сейчас базовая версия `0x00010000`.
- `OTA_MANUFACTURER_CODE` (`0x1234`) и `OTA_IMAGE_TYPE` (`0x5678`) должны совпадать в прошивке, OTA-файле и индексе Z2M.

Пример следующего выпуска: собрать целевую прошивку с `OTA_FILE_VERSION` равной `0x00010001`, затем упаковать именно её с `--version 0x00010001`. Для следующих обновлений увеличить значение снова. Не меняйте `zcl_version` ради номера релиза.

## Первая установка

Нынешняя таблица содержит только `factory`; для OTA нужны `otadata` и два слота `ota_0`/`ota_1`. Поэтому первую OTA-совместимую версию и новую таблицу разделов нужно прошить по USB. Данные Zigbee storage/spiffs переезжают на другие адреса, поэтому после этой миграции устройству может понадобиться повторное сопряжение, а SPIFFS-образы шрифтов надо заново записать из новой сборки.

В таблице оставлено по 1280 KiB на каждый app-слот. Текущий образ был почти 1216 KiB, поэтому после добавления OTA-кода обязательно проверить размер новой сборки перед прошивкой.

## Сборка OTA-файла

После сборки целевой версии приложения:

```powershell
python .\outputs\make_zigbee_ota.py .\build\zigbee_CO2.bin --version 0x00010001 --output-dir .\outputs\ota_release
```

Упаковщик создаёт папку `ota_release` с `co2-<version>.ota` и `index.json`. Скопируйте эту папку в каталог Zigbee2MQTT рядом с `configuration.yaml` (для Docker — внутрь смонтированного каталога данных), затем укажите индекс:

```yaml
ota:
  zigbee_ota_override_index_location: "ota_release/index.json"
```

В индексе прошивка указана путём `ota_release/co2-<version>.ota`, относительно каталога `configuration.yaml`. После перезапуска Z2M проверьте доступность обновления и запустите его для устройства.

Текущий исходник и таблица разделов подготовлены в `outputs`; проект пока не собирался и OTA не проверялся на устройстве.


# От Codex 
Что уже готово
После первой прошивки по USB устройство работает с OTA-разметкой: есть два слота приложения и служебный раздел otadata. При обновлении Zigbee2MQTT передаёт только файл приложения. ESP32-H2 записывает его в свободный слот и после завершения перезагружается с новой прошивкой.
Обычные обновления приложения теперь можно делать по Zigbee. Таблица разделов и загрузчик через этот механизм не обновляются. Файловая система display_fs тоже не входит в OTA-файл: если меняются шрифты или другие файлы на экране, их обновление нужно организовать отдельно.
Выпуск новой версии
1. В исходнике прошивки увеличьте OTA_FILE_VERSION. Например, после 0x00010000 поставьте 0x00010001. Версия должна быть больше уже установленной. zcl_version не меняйте: это версия стандарта ZCL, а не номер релиза.
2. Соберите прошивку из корня ESP-IDF-проекта:
```powershell
   idf.py build
```   
   Убедитесь, что сборка завершилась сообщением Project build complete.
3. Упакуйте полученный build\zigbee_CO2.bin в формат Zigbee OTA. Значение --version должно точно совпадать с OTA_FILE_VERSION из исходника:
```powershell
   python "D:\Users\Nick\Documents\Codex\2026-10-03\6827-co2-zigbee-update-attempt-co2\outputs\make_zigbee_ota.py" `
     .\build\zigbee_CO2.bin `
   --version 0x00010001 `
   --output-dir .\ota_release
```
   Скрипт создаст ota_release\co2-00010001.ota и ota_release\index.json. Для следующего выпуска увеличьте обе версии, например до 0x00010002.
4. Скопируйте папку ota_release в каталог данных Zigbee2MQTT рядом с configuration.yaml. В Docker она должна попасть именно в каталог, доступный контейнеру, а не только на хосте.
5. Добавьте в существующий блок ota: в configuration.yaml путь к индексу:
```yaml
   ota:
   zigbee_ota_override_index_location: ota_release/index.json
```
   Если блок ota: уже есть, добавьте строку внутрь него — второй блок с таким же именем создавать нельзя. Zigbee2MQTT поддерживает локальный OTA-индекс; после изменения конфигурации перезапустите Z2M. Документация Zigbee2MQTT: OTA-конфигурация
   Запуск обновления
   В интерфейсе Zigbee2MQTT откройте устройство CO2 и сначала запустите проверку обновления. Z2M должен показать доступную версию. Затем нажмите Обновить.
   Проверка и установка доступны и через MQTT:
```
   zigbee2mqtt/bridge/request/device/ota_update/check
```
```json
   {"id":"CO2"}
```
   Когда Z2M подтвердит, что обновление доступно, отправьте запрос на установку:
```
   zigbee2mqtt/bridge/request/device/ota_update/update
```
```json
   {"id":"CO2"}
```
   Вместо CO2 можно указать IEEE-адрес устройства. Эти темы и форматы запросов описаны в документации Z2M. Руководство Zigbee2MQTT по OTA
   Во время и после обновления
   Оставьте устройство под питанием и не отключайте его, пока Z2M не сообщит об окончании. В состоянии устройства появится update.state: "updating" и прогресс; после завершения контроллер перезагрузится. Обновление может занять заметное время — Z2M предупреждает, что длительность зависит от устройства и качества сети. Статусы и длительность OTA в Zigbee2MQTT
   После перезагрузки проверьте в логах запуск приложения, появление CO2 в сети и новые показания в Z2M. Повторное сопряжение обычно не требуется: устройство сохраняет Zigbee-данные в отдельном разделе.
   Если проверка не находит обновление, проверьте три вещи: версия в прошивке и упаковщике совпадает; версия новее установленной; Z2M видит и индекс, и .ota файл по указанным путям. Одинаковую или более старую версию Z2M может не предложить. Ограничения проверки версии
