# Zigbee-монитор CO₂

Открытый проект монитора качества воздуха в помещении на базе ESP32-H2 и датчика Sensirion SCD40. Устройство передаёт по Zigbee концентрацию CO₂, температуру, относительную влажность и оценку освещённости, а также показывает измерения на круглом TFT-дисплее GC9A01.

## Возможности

- **CO₂, температура и влажность:** измеряются датчиком SCD40 по I²C.
- **Zigbee:** прошивка настраивает ESP32-H2 как Zigbee Router и предоставляет Zigbee2MQTT стандартные кластеры измерений.
- **Освещённость:** фоторезистор с делителем напряжения подключён к АЦП ESP32-H2. Показание используется для оценки освещённости в Zigbee и автоматической регулировки яркости экрана.
- **Автоматическая подсветка:** ШИМ управляет внешним N-канальным MOSFET, который регулирует подсветку GC9A01. Яркость изменяется плавно в диапазоне 10–100%.
- **Круглый дисплей:** экран GC9A01 с разрешением 240 × 240 показывает шкалу CO₂, крупное значение, температуру, влажность и состояние подключения к Zigbee.
- **Сглаженная графика:** глифы и иконки экрана хранятся в файловой системе SPIFFS как изображения с глубиной 4 бита на пиксель.
- **Поддержка Zigbee OTA:** прошивка содержит OTA Upgrade client, а в репозитории есть упаковщик OTA-образов. Инструкция по настройке и выпуску обновлений — в файле [OTA_README_RU.md](main/OTA_README_RU.md).
- **Файлы для изготовления платы:** архив Gerber находится в папке [`hardware/gerber`](hardware/gerber/).

## Аппаратная часть

| Компонент | Назначение |
| --- | --- |
| ESP32-H2 Mini | Основной контроллер и радиомодуль Zigbee на базе IEEE 802.15.4 |
| Sensirion SCD40 | Измерение CO₂, температуры и относительной влажности |
| TFT GC9A01, 240 × 240 | Круглый цветной дисплей |
| Фоторезистор и резистивный делитель | Измерение окружающего освещения |
| N-канальный MOSFET | Управление подсветкой GC9A01 и её регулировка по ШИМ |
| Кнопка | Сброс настроек Zigbee при удержании в течение 3 секунд |

### Подключение выводов

| Сигнал | GPIO ESP32-H2 | Примечание |
| --- | ---: | --- |
| SCD40 SDA | GPIO10 | Линия данных I²C; адрес датчика `0x62` |
| SCD40 SCL | GPIO11 | Тактовая линия I²C |
| GC9A01 SCLK | GPIO12 | Тактовая линия SPI |
| GC9A01 MOSI / SDA | GPIO14 | Данные SPI; MISO дисплею не требуется |
| GC9A01 CS | GPIO2 | Выбор микросхемы |
| GC9A01 DC | GPIO1 | Выбор данных или команды |
| GC9A01 RES | GPIO3 | Сброс дисплея |
| Затвор MOSFET подсветки | GPIO0 | ШИМ 20 кГц; MOSFET замыкает BLK на низкий уровень, чтобы выключить подсветку |
| Средняя точка делителя фоторезистора | GPIO5 | Канал АЦП ADC1 channel 4 |
| Кнопка | GPIO4 | Активный низкий уровень; удержание 3 секунды стирает Zigbee-данные и перезапускает устройство |

Фоторезисторный делитель подключён между 3,3 В и GND, его средняя точка соединена с GPIO5. Для управления подсветкой используется внешний MOSFET в нижнем плече ключа; не подключайте вывод BLK дисплея напрямую к GPIO0.

## Работа экрана

Шкала CO₂ показывает диапазон **400–2000 ppm** и использует следующие цвета:

| Уровень CO₂ | Цвет |
| --- | --- |
| Ниже 800 ppm | Зелёный |
| От 800 до менее 1000 ppm | Жёлтый |
| От 1000 до менее 1500 ppm | Оранжевый |
| 1500 ppm и выше | Красный |

Цвет значений и иконок температуры и влажности меняется в зависимости от показаний:

| Измерение | Цветовые пороги |
| --- | --- |
| Температура | Ниже 18 °C — синий; от 18 до 26 °C включительно — зелёный; выше 26 °C — красный |
| Относительная влажность | Ниже 30% — красный; от 30% до менее 40% — жёлтый; от 40% до 60% включительно — зелёный; выше 60% до 70% включительно — жёлтый; выше 70% — красный |

Датчик освещённости откалиброван по двум опорным измерениям, поэтому значение в люксах является оценочным, а не результатом точного люксметра. Показания фильтруются, а яркость плавно меняется к целевому значению.

## Zigbee и Zigbee2MQTT

Прошивка создаёт endpoint 1 со следующими стандартными кластерами измерений:

| Измерение | Zigbee-кластер |
| --- | --- |
| Освещённость | `0x0400` |
| Температура | `0x0402` |
| Относительная влажность | `0x0405` |
| Углекислый газ | `0x040D` |
| OTA Upgrade client | `0x0019` |

Устройство объявляет производителя `Custom` и модель `ESP32H2_CO2`. Zigbee2MQTT может отображать стандартные измерения как свойства устройства. Качество связи определяет Zigbee-сеть; SCD40 его не измеряет.

В прошивке устройству назначена роль Zigbee Router. Выбор его в качестве родителя или маршрута для других устройств зависит от координатора, топологии сети, качества связи и решений протокола маршрутизации Zigbee.

### Внешний конвертер Zigbee2MQTT

Для единообразного отображения измерений и поддержки OTA Zigbee2MQTT нужна модель устройства. В репозитории есть конвертер `zigbee2mqtt/ESP32H2_CO2.mjs` для модели `ESP32H2_CO2`.

Скопируйте файл в папку `external_converters` рядом с `configuration.yaml` Zigbee2MQTT и перезапустите Z2M. Если конвертер не загрузился, проверьте, что внешние JavaScript-конвертеры разрешены в настройках Zigbee2MQTT. Конвертер добавляет свойства температуры, влажности, CO₂ и освещённости, а также объявляет поддержку OTA.

Чтобы проверить пользовательское OTA-обновление, откройте окно OTA устройства в Zigbee2MQTT, выберите **Пользовательский индекс** и укажите адрес индекса в репозитории:

```text
https://raw.githubusercontent.com/NickBorodulin/zigbee-co2-monitor/main/OTA/index.json
```

Индекс должен ссылаться на соответствующий файл `.ota`, а версия прошивки в нём должна быть выше установленной на устройстве. Упаковка образа и выпуск OTA-версии описаны в [OTA_README_RU.md](main/OTA_README_RU.md).

Удерживайте кнопку на GPIO4 не менее 3 секунд, чтобы стереть сохранённые данные Zigbee и перезапустить устройство. После перезапуска разрешите подключение новых устройств в Zigbee2MQTT, чтобы выполнить сопряжение заново.

## Таблица разделов и OTA

В [`partitions.csv`](partitions.csv) заданы два слота приложения OTA по 1344 КиБ, а также разделы NVS, хранилище Zigbee и раздел SPIFFS размером 64 КиБ для экранных ресурсов. Первую прошивку с этой таблицей разделов необходимо выполнить по USB. Последующие OTA-обновления передают только образ приложения; загрузчик, таблица разделов и ресурсы `display_fs` таким способом не обновляются.

В прошивке и упаковщике сейчас используются следующие идентификаторы OTA:

| Параметр | Значение |
| --- | --- |
| Базовое значение `OTA_FILE_VERSION` | `0x00010000` |
| `OTA_MANUFACTURER_CODE` | `0x1234` |
| `OTA_IMAGE_TYPE` | `0x5678` |

Увеличивайте `OTA_FILE_VERSION` для каждого выпуска и передавайте то же значение в `make_zigbee_ota.py`. Подробная инструкция по настройке Zigbee2MQTT, упаковке образа, запуску обновления и диагностике находится в [main/OTA_README_RU.md](main/OTA_README_RU.md).

## Сборка и прошивка

Проект разрабатывается под **ESP-IDF v6.0.2** для цели `esp32h2`. Зависимости указаны в [`main/idf_component.yml`](main/idf_component.yml) и устанавливаются менеджером компонентов ESP-IDF.

1. Установите ESP-IDF и откройте настроенную командную строку или терминал ESP-IDF.
2. В корне репозитория выберите целевую платформу:

   ```powershell
   idf.py set-target esp32h2
   ```

3. Откройте настройки проекта:

   ```powershell
   idf.py menuconfig
   ```

   В разделе **Partition Table** выберите пользовательскую таблицу разделов CSV и укажите имя файла `partitions.csv`. Сохраните настройки и выйдите. Сгенерированный `sdkconfig` намеренно не хранится в Git.

4. Соберите приложение и образ файловой системы дисплея:

   ```powershell
   idf.py build
   ```

5. Прошейте плату через USB и откройте монитор последовательного порта, заменив `COM7` на порт вашей платы:

   ```powershell
   idf.py -p COM7 flash monitor
   ```

Файл CMake компонента создаёт образ SPIFFS из `main/display_fs` и добавляет его к операции прошивки.
